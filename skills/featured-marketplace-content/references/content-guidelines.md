# Content Guidelines

## SEO Role

Featured agent and skill pages support Buda's SEO acquisition loop:

- Hub pages collect and internally link curated pages.
- Detail pages target specific long-tail queries and explain a concrete workflow.
- CTAs route users toward installation or the broader marketplace.

Write for searchers who want to solve a workflow, not for generic browsing.

## Attribution

Many marketplace items come from open-source or community creators. Preserve attribution:

- Use the marketplace/GitHub creator as `author.name`.
- Use roles such as `Open-source Creator`, `Community Creator`, or `Marketplace Creator`.
- Use `Buda Team` only for Buda-owned/editorial items.

Avoid wording that makes a community item sound Buda-owned.

Recommended:

- "an open-source skill that can be used with Buda agents"
- "a community-authored marketplace skill"
- "a skill for agents that need to..."

Avoid for third-party items:

- "Buda skill"
- "official Buda skill"
- "built by Buda"
- "our skill" unless Buda is the author

## Tone

Use clear, concrete, helpful copy:

- Describe what the item does.
- Explain when to use it.
- Mention inputs and outputs only in natural workflow language.
- Avoid hype and unsupported guarantees.
- Vary `metaDescription` and hero phrasing. Do not start every card with "An open-source skill that..." or "A community-authored skill that...".
- Preserve attribution through `author`, source notes, and factual wording; the card subtitle should sell the workflow benefit, not repeat the license/ownership label.

Do not claim:

- guaranteed rankings
- guaranteed accuracy
- official endorsement
- production readiness beyond what the source supports
- user reviews or testimonials unless provided and authorized

## FAQ Rules

FAQ answers should answer from the item/page perspective.

Prefer:

```txt
Yes. This skill outputs an editable PPTX file that you can open and refine in PowerPoint.
```

Avoid:

```txt
The marketplace description says it exports to PPTX.
```

## Markdown Sections

`overviewMarkdown` and `useCasesMarkdown` should remain easy for an AI or partner to maintain:

- Use short paragraphs.
- Use bullet lists.
- Avoid custom HTML.
- Keep claims aligned with visible/source content.

## Categories And Tags

Use existing marketplace-friendly categories when possible:

- Engineering
- Marketing
- Sales
- Operations
- Research
- Finance
- HR
- Support
- Data
- Design
- Personal
- Product

Tags should be specific enough to help scanning, usually 3 items.
